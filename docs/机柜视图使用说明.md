# 机柜设备管理使用说明

## 从源码启动

在项目目录执行：

```powershell
.\venv\Scripts\python.exe -X utf8 -m src.main
```

进入“设备管理”，默认显示机柜视图；右上角三个图标可以选择机柜、列表、方块视图，并保存选择。

搜索、机房筛选和三种视图切换集中在标题下方的工具栏。机柜视图左侧为机柜工作区，右侧为设备详情；待上架设备固定在工作区上方，数量较多时可以横向滚动，浏览机柜底部不会把待上架设备滚走。机柜标题右侧齿轮提供编辑和删除，细进度条表示 U 位使用率。

设备详情默认隐藏，单击服务器后展开。右上角的“×”关闭详情并恢复机柜可用宽度，不影响连接和正在执行的任务。关闭后，刷新状态或拖动设备不会自动打开详情；再次单击设备即可展开。

也可在启动命令末尾添加 `--devices`，直接打开设备管理页。未创建机柜时展示的是机柜外观示意，点击“创建第一个机柜”保存真实机柜；已有设备以拟物服务器面板显示在待上架区，点击后可安排位置。机柜和服务器使用 Qt 原生矢量绘制，支持缩放，服务器面板显示硬盘托架、散热网、铭牌和连接状态灯。

机柜使用浅色金属外观。悬停、选中和上架有短过渡动画，执行任务时状态灯缓慢变化；动画不改变槽位或设备位置。

## 创建机柜与设备上架

1. 点击“新增机柜”，填写编号、名称、机房和容量。默认 42U，支持 1–60U。
2. 点击“添加”，或直接点击机柜内的空槽。
3. 填写设备 SSH 信息，选择机柜、起始 U 位和高度。也可以选择“暂不上架”。
4. 起始 U 位是设备底部。例如起始 U09、高度 2U，实际占用 U09–U10。
5. 点击“推荐空位”查找第一段连续空槽，或自行选位。冲突和越界会明确提示，不会挤动已有设备。
6. 保存后点击设备面板，右侧显示该设备的详情和操作。

旧设备不会被自动塞入机柜，统一显示在“待上架设备”区域；点击设备，选择“调整位置 / 下架”，再填写位置。

## 拖动上架与移位

按住待上架服务器面板，拖到机柜内的目标 U 位后松开，即可保存上架位置。拖动时绿色区域显示设备将占用的 U 位；红色提示表示位置冲突或越界，不能落位。起始 U 是设备底部，多 U 设备向上占用空间。

尚未创建任何机柜时，也可以直接将服务器拖到机柜示意图，系统会在同一次保存中创建“默认机柜”（A01、42U）并将该设备放在 U01。之后可以编辑机柜名称、机房和容量。

已上架服务器也可拖动调整位置或跨机柜迁移，原位置在成功保存后释放。拖动过程中把鼠标移到滚动区域上下边缘可自动滚动查看长机柜；移到左右边缘可切换查看并排机柜。取消拖动、无效落位或保存失败都保留原位置；下架仍使用“调整位置 / 下架”表单。

连接中或巡检中的设备暂时不能拖动。拖动只修改位置，不复制设备、不修改登录信息，也不会运行 SSH 命令。

## 点击设备后可以做什么

- 连接设备，或断开当前设备。
- 一键巡检：连接成功后弹出巡检窗口，顶栏显示设备名称和地址。关闭或收起弹窗后任务继续运行，可通过“查看巡检进度 / 结果”重新打开；同一运行任务不会重复启动。
- AI 排障、日志收集：进入对应页面，由用户继续操作。
- 实时监控：打开目标设备的监控窗口。
- 调整位置、迁移到其他机柜，或选择“暂不上架”将设备下架。
- 查看最近一次手动巡检摘要，以及已实际导出的报告文件。

齿轮菜单继续提供切换 root、编辑、删除、知识库和脚本库。切换 root 的可用状态与当前登录及连接状态一致。

切换 root 时输入当前登录账户的 sudo 密码。验证成功后，后续命令以 root 执行，SSH 登录账户保持不变；文件上传和下载仍使用登录账户权限。

系统沿用单个主运维会话。操作另一台设备时会提示切换连接；连接失败或取消后不启动巡检。巡检、AI 排障命令、日志提取和报告分析运行期间，需要先等待或停止任务再切换设备。连接中的目标设备不能编辑或删除。

## 批量巡检

1. 打开左侧“批量巡检”，无需先手动连接设备。
2. 第一步只显示设备列表。勾选设备，或点击“全选设备”，再点击“下一步”。
3. 第二步选择巡检项，支持全选、取消全选和返回修改设备。点击“下一步”只进入待开始页面，不建立连接或执行命令；可以点“上一步”继续修改巡检项。
4. 第三步点击“开始巡检”后，系统按设备列表顺序逐台建立独立 SSH 连接、执行检查并断开。页面只显示此次设备的状态、进度条和百分比，不展开巡检项与原始输出。进度按已完成巡检项数量计算，不表示耗时或设备健康程度。连接失败标记“失败”；停止保留实际完成百分比，未启动的设备标记“未执行”。单台失败会继续下一台。
5. 批次结束后，点击设备行后的“导出”保存该设备的原始报告；“分析导出”只对执行完成的设备可用。“导出全部报告”保存每台已开始执行设备的文本报告，未执行的取消设备不生成空报告。需要新一轮巡检时点击“重新选择设备”。

报告导出成功后自动打开所在文件夹；批量导出仅打开一次保存目录。取消保存或保存失败不会打开文件夹。若文件夹打开失败，已保存的报告继续保留。

“停止批量巡检”会请求停止当前采集并取消后续设备，保留已采集结果。未开始的取消设备不覆盖以前的巡检摘要和报告链接。排队中和正在执行的设备暂时禁止编辑、删除或拖动，批量巡检与单台巡检不能同时启动。

批量模式使用保存的登录凭据和规范检查项，不自动提权；权限不足会体现为未获取或检查结果提示。需要交互式 OTP 的旧设备请从设备详情单独连接巡检。

“已连接”仅表示 SSH 会话可用；“未连接”不代表设备离线。最近巡检结果与连接状态分别显示，并附带巡检时间。定时巡检继续使用原有页面和报告目录，不写入第一版机柜详情的手动巡检摘要。

## 管理和检索

添加和编辑设备的表单按设备信息、SSH 连接、机柜位置分组；新增和编辑机柜使用相同的浅色表单样式。取消位于左侧，保存位于右侧，输入框、下拉框与数字调节按钮保持统一配色。

左下角头像打开个人菜单，可进入“个人中心”“设置”或“退出登录”。个人中心保存本地显示名称；设置窗口包含“大模型配置”和“定时巡检配置”，原主导航的这两个入口已移入设置。首页对应快捷入口会打开设置并定位分类。关闭设置窗口不会停止任务或清空未保存的模型编辑内容。

“退出登录”按当前版本约定退出整个程序；运行中的巡检、报告分析、SSH 连接、定时任务或大模型连接测试会阻止退出，需要先等待或停止任务。本地个人资料保存在 `src/config/profile.json`，不提交到 Git。

搜索可按设备名称、IP、产品或机柜查找；机房下拉框筛选机柜。搜索不会改变设备真实 U 位，匹配的设备面板高亮显示。

机柜容量可以修改，但缩小后不能使任何设备越界。删除机柜前必须迁移或下架全部设备。下架保留设备连接配置；删除设备继续需要确认，当前已连接设备需要先断开。

已有位置异常的设备进入“位置待修复”区，不参与有效占用率统计。允许逐条修复旧记录；未修改的旧异常记录暂时保留。新增位置和修改后的位置必须有效，不能引入新的冲突或越界。

## 保存与兼容

源码模式使用 `src/config/servers.json` 保存设备、机柜和视图偏好。旧格式首次成功保存前生成 `servers.json.v1.bak` 本地备份；原子替换保存失败时保留原文件。读取配置失败时禁止覆盖原文件，需先修复配置再重启。

最近手动巡检摘要位于同目录 `inspection_history.json`，包含设备 ID、时间、计数和实际导出的报告路径，不保存密码。报告移走后会提示文件不存在。以上本地配置、备份和巡检输出均不提交到 Git。

## 毕业设计可讲的实现

机柜空间用整数区间建模：设备从 `start` 到 `start + height - 1`。两个区间 `[a,b]` 和 `[c,d]` 在 `max(a,c) <= min(b,d)` 时重叠；从低位向高位扫描即可推荐连续空位。

界面、空间规则和 SSH 调度分开：界面发出设备 ID 和动作，主窗口校验目标、建立连接并启动任务。连接请求令牌用于忽略过期回调，巡检开始时冻结设备快照，结果和报告始终绑定启动目标。

巡检状态仍由现有采集规则判定，AI 根据实际输出辅助解释。没有 AI 配置时，基础巡检和原始报告导出仍可独立使用。
