# 设备内巡检工作区

问题：设备详情点击一键巡检后跳转到全局侧栏巡检页，失去设备上下文。

实现：设备管理内部打开巡检工作区，顶栏显示设备名称与地址，并提供“返回机柜”。巡检项、执行输出、结果预览和报告操作复用 InspectionPage 类；全局侧栏继续保留独立入口。两个界面共享采集、判定及报告代码，不复制巡检引擎。

返回机柜只隐藏工作区，任务继续运行，设备状态与“查看巡检进度”入口保持可见；完成后可以查看巡检结果。同一任务重新打开时不重复启动。新巡检仍由“一键巡检”启动，已有工作区结果可通过“查看巡检”重新打开。

连接成功后才启动，连接失败不打开巡检；切换设备的中间断开过程不再闪回首页。两处巡检入口共用任务忙碌校验，防止同时操作同一个主会话；后台巡检也阻止切换设备与断开连接。

进度恢复必须检查设备内工作区自身的活动线程，不能根据其他入口的任务推断，避免打开旧结果冒充当前进度。历史摘要与导出文件继续使用任务启动时冻结的设备 ID 和任务 ID。

验证：109 项测试通过，覆盖设备内导航、返回和恢复、停止与目标绑定、两个入口互斥及旧结果防混淆。使用模拟 SSH 生成界面截图与结果，未连接真实 Linux 主机。
