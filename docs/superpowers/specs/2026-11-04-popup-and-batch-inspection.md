# 单台巡检弹窗与批量巡检

依据：用户要求单台一键巡检使用弹出框，左侧入口改为批量巡检，执行所有勾选设备。

- 单台继续复用 InspectionPage，在可收起的 QDialog 中显示设备上下文、进度、结果与报告操作。关闭窗口仅隐藏；工作区、机柜和导航保持可见。
- 左侧 BatchInspectionPage 继承检查选择与报告组件，增加设备勾选表格、全选、刷新、执行状态及全部原始报告导出。不依赖主窗口当前 SSH 连接。
- 批量工作线程冻结勾选设备和检查项；逐台创建独立 SSH 客户端，失败后继续，始终在 finally 中断开。凭据仅在线程内部读取，结果快照不包含密码。
- 任务按设备 ID 与独立任务 ID 归属，查看结果、AI 分析和报告路径均绑定所选结果。未完成行清空旧输出并禁用导出，避免误导出其他设备结果。
- 停止使用取消事件并请求停止当前流式采集，UI 不阻塞等待。未执行设备显示已取消，但不替换其真实历史与报告。
- 所有批量目标提前标记等待巡检，防止排队期间修改身份、删除或拖动；完成、失败、取消后分别释放状态。单台连接请求未完成时也禁止启动批量任务。
- 批量与单台共用忙碌保护，退出时要求先结束活动任务。独立审查发现的排队身份变化、未执行取消覆盖历史、连接请求竞争均已加入回归测试。

验证：118 项测试通过，包括 Qt 弹窗、无需全局连接的批量入口、勾选目标冻结、独立连接与失败继续、取消、逐台历史与导出报告归属。通过隔离的三台演示设备（包含一台连接失败）检查 Qt 截图。本次未连接真实 Linux 主机。
