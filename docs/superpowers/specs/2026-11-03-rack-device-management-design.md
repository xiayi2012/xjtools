# 机柜可视化设备管理设计

日期：2026-11-03

项目：AI智能Linux运维系统

状态：设计待评审，尚未实现。当前代码基线：`4830dec`。

## 目标与方案选择

将现有设备管理扩展为“设备资产 → 机柜上架 → 设备详情 → 运维操作”的完整流程。继续使用 Python、PyQt6 与现有 SSH、巡检、AI 排障和报告能力。

可选方案：

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 二维机柜正面视图，推荐 | U 位清晰、点击准确、复用现有 Qt、适合论文与答辩 | 需要绘制机柜和设备面板 |
| 普通卡片上增加机柜标签 | 实现较快 | 不能直观展示空槽、空间占用和上架位置 |
| 三维机房 | 空间展示强 | 引入额外渲染与交互成本，对当前运维流程帮助有限 |

第一版采用二维拟物机柜，设备面板、机架导轨、螺丝孔、散热孔和状态灯使用 Qt 绘制。重点保证可读性，避免装饰遮挡主机名称与地址。

## 页面与交互

设备管理顶部保留图标分段切换，扩展为“机柜 / 列表 / 方块”三个视图，新版首次进入默认机柜视图；之后记住用户选择。原有产品分组在列表和方块视图中继续保留。

示意布局（示意名称，不代表已存在的设备）：

```text
设备管理      [搜索设备名 / IP]   [机柜▣ 列表☰ 方块▦]  [新增机柜] [添加设备]
机房：全部  ▾
┌─ A01 · 42U ──────────┐  ┌─ A02 · 42U ──────────┐  ┌─ 设备详情 ──────────┐
│ 已用 6U / 空闲 36U   │  │ 已用 2U / 空闲 40U   │  │ EDR-01             │
│ 42 ── 空槽 ────────  │  │ 42 ── 空槽 ────────  │  │ 192.0.2.10:22      │
│ ...                  │  │ ...                  │  │ A01 / U09–U10 / 2U │
│ 10 ┌ EDR-01 ─── ● ┐  │  │ 02 ┌ Linux-02 ── ○ ┐ │  │ SSH：未连接        │
│ 09 └ 192.0.2.10 ──┘  │  │ 01 └ 192.0.2.11 ──┘ │  │ [连接] [一键巡检]  │
│ ...                  │  │                      │  │ [AI排障] [日志收集]│
│ 01 ── 空槽 ────────  │  │                      │  │ [实时监控]     [⚙] │
└──────────────────────┘  └──────────────────────┘  └────────────────────┘
待上架设备：未填写位置的已有设备，点击详情后选择上架。
```

- 机柜顶部显示编号、机房、容量、已用 U、空闲 U；使用率按已占 U 位计算。
- U 位从底部 U01 向顶部递增，42U 机柜顶部为 U42。界面支持滚动查看完整机柜；多机柜使用水平滚动，不将设备压缩到无法点击。
- 设备至少显示名称、地址、产品、占用范围及连接状态，悬停提供完整文本。搜索只高亮匹配设备、过滤无关机柜，不改变设备在柜内的物理位置。
- 空槽可点击打开添加设备表单，并预选机柜及起始 U 位；设备点击打开右侧详情面板。窄窗口时详情使用可滚动弹窗。
- 待上架区始终可访问；旧数据不强制自动分配位置。无机柜时显示创建机柜入口和待上架设备。
- 第一版使用表单选择位置并预览，包含按钮、键盘与工具提示；拖拽上架留作后续增强，不作为基础操作的唯一入口。

## 添加、编辑和位置调整

添加设备保留名称、产品、主机地址、SSH 端口、用户、密码及切换 root 设置，新增机柜、起始 U、设备高度（默认 1U）字段。

1. 选择“暂不上架”，或选择一个机柜。
2. 选择起始 U 位和高度，旁边预览占用范围，例如“U09–U10，共 2U”。起始 U 指设备底部。
3. 提供“推荐空位”按钮，从低位向高位寻找第一段足够的连续空位，不自动挤动其他设备。
4. 提交前检查槽位冲突、越界、设备标识重复以及必填字段；冲突时显示冲突设备和范围，保留已填内容。
5. 保存后立即刷新机柜并选中新设备；未连接的新增设备显示“未连接”，不虚构健康状态。

编辑设备可迁移机柜、调整位置与高度；将机柜设置为“暂不上架”即下架，保留设备与连接信息。编辑时排除设备自身原占用范围。下架与删除资产分别处理，删除继续使用现有确认弹窗。已连接设备修改主机地址、端口、登录用户或删除前，要求先断开连接，避免资产信息与实际会话不一致。

## 机柜管理

新增机柜填写唯一编号、显示名称、机房名称和容量；默认 42U，可选择 12U、24U、42U、48U，或输入 1–60U。编号和名称不可空，编号去除两端空格后大小写不敏感去重。

可编辑名称、机房和容量。缩小容量前检查现有设备，越界时拒绝保存并列出受影响设备。非空机柜禁止删除，提示先迁移或下架其中设备；空机柜删除需要确认。机柜删除不连带删除资产。

## 设备详情与运维入口

详情分为基本信息、机柜位置、会话状态、最近巡检摘要与操作区。密码始终不显示。最近巡检摘要包含时间、结果统计和报告入口，无记录时显示“尚未巡检”；报告文件不存在时明确提示，不生成虚假报告或指标。

主要操作：连接 / 断开、一键巡检、AI 排障、日志收集、实时监控。切换 root、编辑、删除、知识库、脚本库继续统一放在最右侧齿轮菜单；切换 root 的可用状态沿用当前规则。

一键巡检复用现有默认勾选的规范巡检项和报告生成流程。已经连接该设备时，进入巡检页并启动一次巡检；首次连接该设备成功后再启动。重复点击期间禁用启动入口，避免重复任务。AI 排障与日志收集仅进入对应页面，不自动发送提问或执行日志提取。

机柜面板上的状态需要明确区分：

| 状态 | 显示与依据 |
| --- | --- |
| 未连接 | 灰色；未建立当前 SSH 会话，不等同于设备离线 |
| 连接中 | 蓝色；等待当前连接请求完成 |
| 已连接 | 青绿色；仅表示 SSH 会话可用 |
| 连接失败 | 红色；本次连接失败，详情显示原因 |
| 巡检中 | 独立任务徽标；不能被普通连接状态覆盖 |
| 最近巡检结果 | 显示时间和正常 / 警告 / 异常 / 未获取数量，独立于连接灯 |

## 会话与任务正确性

当前应用使用一个全局 SSH 会话。第一版保留单会话模型，不引入多设备并发操作。

- 所有设备动作携带不可变设备 ID 和动作类型。点击设备 B 的巡检时，不能复用设备 A 的连接运行。
- 无会话：连接目标设备，成功后消费待执行动作；认证取消或失败后清空动作，不进入操作页。
- 当前会话属于目标设备：验证连接有效后执行动作。
- 当前会话属于其他设备：先提示将从 A 切换到 B，明确设备名称和地址；取消时保持 A 会话不变。确认后关闭旧会话，连接 B。
- 连接中不允许发起第二个连接或更换目标。为连接请求附加目标 ID 和请求令牌，忽略过期回调；成功后再次校验目标，且待执行动作只消费一次。
- 巡检、AI 命令或日志提取仍在运行时，阻止切换设备和断开连接，提示等待任务完成或通过现有停止流程结束。停止完成前不销毁任务仍持有的 SSH 客户端。
- 任务结束时使用启动时冻结的设备 ID、地址和名称保存结果，禁止用后来选中的详情设备覆盖归属。
- 普通“连接”动作只连接，不自动触发巡检。root / sudo 处理复用当前流程；不额外声称已经获得常驻 root shell。

## 存储与兼容

机柜资产和设备记录一起写入现有 `servers.json`，顶层增加 `schema_version: 2`、`racks` 和 `preferred_view`；保留 `servers` 数组，设备新增 `rack_id`、`rack_start_u`、`rack_height_u`。机柜 ID 使用 UUID，名称可改而引用不变。

统一存储便于在同一次保存中验证设备与机柜引用并原子替换文件。写入使用同目录临时文件，成功后替换；失败时不修改页面当前已提交数据，显示可理解的错误。凭据继续使用现有加密字段，不在新存储或日志中复制明文密码。

兼容规则：旧文件缺少 `racks` 时按空数组读取；缺少位置字段的设备进入待上架区；设备现有 ID 保持不变。迁移首次写入前备份原文件至本地配置目录。读取失败时显示错误，禁止把空数据自动覆盖原文件。

存量记录若引用不存在的机柜、位置越界或互相重叠，进入“位置待修复”区域并保留原字段供编辑，不隐藏设备，也不计入有效占用率。新保存的记录必须全部满足位置规则。

巡检摘要独立保存至配置目录下的历史索引，包含设备 ID、任务时间、计数与可选报告路径，不重复存储密码和完整 SSH 输出。用户手动导出报告时才记录实际生成的文件路径。历史索引保存失败不改变真实巡检完成状态，单独提示无法保存历史。

## 代码职责

- 新增纯 Python 机柜模型模块：容量和位置校验、冲突检测、空位推荐及兼容读取，不依赖 Qt，方便初学者理解与测试。
- 新增机柜视图模块：绘制、选择、搜索高亮、详情展示，通过信号请求操作，不直接建立 SSH 连接。
- 设备管理页负责三种视图、机柜管理与添加 / 编辑表单，复用现有设备信号和齿轮操作。
- 主窗口统一处理目标设备、会话切换和待执行动作，再交给巡检、排障、日志页面。
- 巡检模块只增加任务归属及摘要完成事件，继续使用当前共享巡检规则，不复制一套判定逻辑。

## 验收与测试

1. 使用 12U 示例柜，在 U03 放置 2U 设备，界面准确占据 U03–U04；推荐空位跳过已用范围。
2. 覆盖顶部边界、多 U 重叠、同柜编辑排除自身、跨柜迁移、满柜、下架、缩容和非空柜删除。
3. 旧配置可加载、密码加密字段不变；新增后重启仍保留机柜、位置和视图选择；保存失败不损坏原文件。
4. 点击面板能看到正确设备资料；三种视图切换后选中目标和 root 菜单状态正确。
5. 使用模拟 SSH 验证 B 的巡检不会落到 A，连接失败 / 取消 / 过期回调不会启动任务，快速双击只启动一次。
6. 任务执行中无法切换设备，报告与最近巡检摘要始终归属于任务启动目标；健康结论沿用当前六类结果。
7. 在 1200×800 窗口及常见缩放下检查长设备名、空柜、满柜、多个机柜、待上架区及完整 42U 滚动。
8. 自动测试通过后，用测试 Linux 主机验证 SSH → 巡检 → 报告全流程；没有真实主机验证时明确标注验证范围。

## 适合毕业设计讲解的内容

- 机柜空间建模：用 U 位区间表示设备占用，完成冲突检测、空位推荐与容量统计。
- 可视化资产管理：将二维机柜、设备信息和运维动作关联，完整展示设备添加、上架、迁移、下架生命周期。
- 面向目标的运维流程：设备 ID 贯穿连接、任务、结果与报告，处理失败、取消和异步回调，防止操作目标错配。
- 规则与 AI 分工：规范巡检规则负责采集与状态判定，AI 基于实际输出辅助解释与报告分析；展示时可关闭 AI 说明基础能力仍能独立运行。

上述为工程实现与流程设计亮点，不宣称自研大模型或发明新的巡检算法。
